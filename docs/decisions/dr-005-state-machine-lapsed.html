DR-005An explicit task state machine, with lapsed distinct from withdrawn

Every task lives in an explicit state machine with named states, live timers and recorded transitions. Silence from the user ends in lapsed, through visible nudges, and lapsed is not withdrawn; silence from the system is an exception the watchdog surfaces.

1Decision

Every task is in exactly one named state, every non-terminal state carries a live timer, and no task reaches a terminal state without an explicit, recorded transition. A user who goes quiet is legitimate: the task moves through visible nudges into lapsed, a terminal state distinct from withdrawn, and a later message from the user revives it. A system that goes quiet is forbidden, as an architectural invariant rather than a procedure: a task with no live timer is an exception, and the watchdog places it on the exceptions board until a person gives it one.

1.1The states

Seven non-terminal states, each with its own timer: received and planning against a planning deadline; awaiting-authority, awaiting-user and awaiting-verdict against the nudge schedule; active against the earliest step deadline; awaiting-third-party against the third party's expected response window, then escalation. Three terminal states with no timer and no further execution: closed, reached only by the user's verdict; lapsed, reached only by the system after the nudge schedule on one of the three awaiting states is exhausted; and refused, reached only from received or planning, before any step executes, when the request falls under what we refuse to do. Expiry of any timer is acted on by the task service on the tick, never by a person, as 02 fixes: a planning deadline is re-planned or escalated, a step deadline re-queued, re-planned or escalated per the step type; the nudge schedule nudges and then writes the lapse event; the third-party window triggers a re-plan, escalate-resume when the re-plan finds a route and a recorded holding window when it does not. A person acts only on what the watchdog places on the exceptions board: a task with no live timer, a check past its deadline, a window expired with no route, a nudge schedule exhausted without its lapse event. Nothing executes before awaiting-authority has been left by the user's own authorisation.

1.2The transitions

Every transition is explicit and recorded; the full list is in 02, and several deserve naming here. Nudges are recorded events on the timer of the three awaiting states, visible to the user and on the task's timeline; the schedule is per task type, and the illustrative default is three nudges, then lapse. Lapse cancels nothing, because nothing is in flight to cancel: a task lapses only from the three awaiting states, and 02's projection of task state from step states puts a task with any step ready, running or checking in active, so no step can be waiting to fire while the user is silent. A lapsed task executes nothing, and its pending and bounced steps are re-planned on revive; a step the new plan no longer needs closes superseded, step state cancelled, which beside withdrawn is one of the two causes of cancelled that 02 defines. Revive takes a lapsed task back to planning on a user message that references it, where the plan and the envelope are re-proposed for one-tap confirmation; no authority survives lapsed, so lapsing costs the user a fresh confirmation and the time, never the task. Withdraw is available from any non-terminal state, cancels every step in flight, and reports any irreversible step that has already fired; it is the user's verdict, "withdrawn by me", and the system can never issue it. A redo verdict closes the parent and opens a linked child in planning; a closed task never re-opens.

1.3The invariant

The invariant is stated in full, identically, in 02 and in the worker console specification, and the build check compares the two copies. This record carries no third copy on purpose: a copy that nothing checks can drift by a word, which is the failure section 3 forbids. Its content is the decision above.

2Rejected alternative(s) and their cost

Implicit states derived from step status and elapsed time
A task is "done" when its steps are done and "abandoned" after some number of days. A task then finishes by arithmetic nobody recorded, which is forgetting by omission, the failure the invariant names, and nothing distinguishes the user's choice from the system's guess.
Silence treated as withdrawal
The system would be filling in the user's verdict. "Withdrawn by me" would carry two meanings, the verdict data would misstate withdrawal rates, and the five-option ceiling of DR-002 would be breached by an invisible sixth. lapsed exists so that the user's silence is recorded as what it is.
Never lapsing; reminders forever
A task holding live delegated authority stays open past its validity window, timers never expire so the exceptions board floods and the watchdog loses its meaning, and the user's inbox becomes the store of record. A terminal state that the user can revive is safer than an open task nobody owns.
A procedure instead of an invariant
A weekly sweep for stale tasks finds them after the damage, and a procedure can be skipped on the one busy night that matters. The watchdog checks the invariant on every task and every timer, always, and the operational duty in 04 is to work the board it produces.

3What this closes off

  • A terminal state reached by timeout, deletion or arithmetic without a recorded transition.
  • A non-terminal state without a live timer. A task without one is an exception by definition, not a backlog item.
  • A timer expiry handled by a person instead of the task service, or an exceptions-board entry the watchdog did not raise.
  • lapsed as a button, a user option or a verdict; and lapsed counted as withdrawn in any measure or make-good rule.
  • A closed task re-opened. Redo spawns a linked child in planning.
  • Any step executing in lapsed, closed or refused.
  • An irreversible step firing under an envelope confirmed before the task lapsed.
  • The invariant's text differing, by a word, between 02 and the worker console.
