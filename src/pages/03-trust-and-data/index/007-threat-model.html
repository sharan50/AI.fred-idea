7The threat model: paths by which a human could see a real value

The first fatal failure is a worker on our side seeing something they should not, and the threat model is organised as the list of paths by which that could happen, each named, and each closed except the two this edition leaves open and 07 declares. A path is closed when a component property, not a procedure, stops the value before it reaches a person, and when the ledger records what happened. The evidence system is on the list, because it is the store people most want to open; so are the ledger itself, the room, the staff of every provider we buy from, the vault, the carrier and the sandbox, and the user's own habits. Figure 3.3 maps the twenty-six paths; Table 3.6 gives each its mechanism and its ledger line. The three paths that run through the room, 5, 6 and 7, all close in software: the browser stream's masking happens server-side before encoding, so nothing on a screen or in a headset is a real value, whoever photographs, tampers or looks, and the format masks, the default paint and the hold of 3.1 cover what no map predicted. The three control rows of Table 4.4 in 04, Clean floor and locker, Device policy and Monitored substitution stations, are each path's record and its deterrent, never its closure. No row of either table claims that a value reaches a screen as a residual, and the site controls and this table can be audited against each other. The proof that the closures hold is the canary test the build sequence in 06 requires at each surface's gate and before the pilot, and its procedure is fixed here. A planted value of every class in Table 3.1, in every normalised form the class lists, enters by each door in turn: typed and pasted into the channel, spoken in a voice note, uploaded, returned by a rail stub through the adapter's proxy, and echoed by a stub institution on each surface. A scripted task then places each on each surface, and a scanner searches for every form of every planted value in the evidence store, every database, cache, queue, backup and replica we run, every log, trace and metric index, the ledger, the console's stream as recorded at a test station, the transcript and the captions, and the relay's outbound store after the window. The gate asserts three things: zero matches; one "placing" and one "placed" or "not confirmed" line per placement; and that the verifier fails closed on an artefact deliberately under-masked for the run and the hash service's screening call refuses a planted value handed to it from the alias zone. Two planted values are never vaulted: a reference in a stub party's recorded shape and a free-text condition from the dictionary, echoed on a stub page and typed into a stub form, which must reach no test station as text; a call carries no planted value, because it carries no value at all. A gate that cannot plant a class has not tested it, and says so in the run's record.
